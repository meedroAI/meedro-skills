name: content-calendar description: Build a shoot-ready content calendar dashboard from competitors' top-performing videos - Meedro-only, zero-credit by default. Pulls videos that already have full transcript data, keeps only patterns that transplant into the user's niche (cross-niche welcome), verifies+auto-fixes every hook against the real transcript, and has Claude write a full ready-to-film script for each recommended video keeping the viral structure/pacing/hook while re-skinning topic and wording. Renders one self-contained HTML dashboard: a weekly content plan that lists each script by day with its funnel stage and full data, plus hook templates, retention structures, full-funnel strategy, and a hero deep-dive. Sections adjust to the user's request. Trigger on "content calendar", "content command center", "recreate competitors' viral videos into my niche", "viral dashboard for my niche".
The user wants a shoot-ready content calendar: pull competitors' best videos, recreate them as scripts in the user's niche keeping the viral structure, and render it as one HTML dashboard. Brief: "$ARGUMENTS".
MEEDRO-ONLY. Use Meedro tools/skills exclusively - never Sandcastles, web search, or any other MCP. If a handle can't be resolved in Meedro, ASK the user; don't reach outside.
PLATFORMS = INSTAGRAM AND TIKTOK ONLY. Every video, creator, and script is Instagram reels or TikTok. Meedro does not cover YouTube Shorts, Facebook, LinkedIn, or anything else - never search for, promise, or reference other platforms. When a tool needs a platform value, it's always 'instagram' or 'tiktok'.
Hard rules (never break)
ZERO-CREDIT BY DEFAULT. The whole build runs on free surfaces. Every video used for a script must ALREADY have a full transcript. If a needed video isn't analyzed, STOP and ask the user to approve analyzing it first (worst-case estimate) - never analyze silently.
LIVE DATA ONLY. Every number/hook/transcript comes from a tool call in this session. Never invent metrics. If a metric isn't returned, omit it.
PATTERN-MATCHED SELECTION, never blind picks. Niche fit is judged on the RECREATED SCRIPT, not the source video. A source qualifies if it (a) has a full transcript, (b) has a transplantable hook+structure+pacing, (c) recreates into a quality script for the user's niche + criteria. Cross-niche sources are allowed and often preferred; tag them. Do NOT filter by whether the original is talking-head vs voiceover/b-roll - a pattern transplants across formats (a talking-head original can become a voiceover script and vice versa). Reject only when the pattern is topic-locked or un-adaptable - high views alone never qualify a video. Exception: user-named inspiration videos are used directly (still hook-verified).
RE-SKIN, DON'T REDESIGN. Recreated scripts keep the original's verified hook PATTERN, pacing, beat count, and emotional triggers. Only niche/topic/examples/wording change. Hero hook stays near word-for-word.
VERIFY + AUTO-FIX EVERY HOOK. The real hook is the transcript's FIRST spoken line - NOT the stored "hook" field or caption (those are usually the CTA or a mid-video line). Re-derive each hook from the transcript before anything is shown; silently correct mismatches and use the corrected hook everywhere (rows, templates, hero).
CLAUDE WRITES THE SCRIPTS directly, applying these rules + the user's criteria + the quality gate below. No external generate/recreate/scripting tool.
SOURCE ON EVERY SCRIPT. Each row/script shows the original video's real link + creator @handle + real views/engagement, next to the recreation for one-click comparison. Never fabricate a link; if none is returned, show @handle + note it's unavailable.
COMPLETE OUTPUTS. Full transcripts/scripts, all rows - no summaries.
EXTENSIBLE. If the user asks for extra data/columns (audio, posting time, duration, save/share rates, caption, hashtags, b-roll, a 2nd variant, another language), include it when Meedro has it or Claude can generate it; if a field isn't available, say so.
FULL TEMPLATES ONLY. Whenever a script template or the original's structure is requested or shown (hero Original->Template->Recreated, a "show me the template" ask, any reusable skeleton), always produce the COMPLETE template of the whole script start to finish - every beat from hook to CTA - never a portion, excerpt, or just the opening. A template covers the entire original script's structure, turned into fill-in-the-blank placeholders, with no beats skipped.
HOW USERS START (handle any of these entry paths)
Users come in different ways. Detect which one from their message and follow it; ask only what's missing.
BY TOPIC / NICHE - "find viral content-marketing videos", "what's going viral in fitness". Search the viral library by topic/niche (search_viral_videos).
BY USERNAME / CREATOR - "find viral videos from @creator", "what are @creator's best videos". Search by that @username (search_viral_videos / analyze the creator's reels).
NAMED COMPETITORS - "check these competitors: @a, @b, @c". Add them, pull their videos, build from those. Users can hand you the exact competitors to study.
NAMED VIDEOS - "use these specific videos" (rule 3 exception). Use those directly.
TWO-STEP (very common) - first they ask you to find/analyze some creators or videos, review the results, and PICK the ones they like; THEN they ask you to turn the picked videos into a content calendar. When they've already chosen videos in an earlier step, build the calendar from that selection - don't re-search from scratch. In every path the goal is the same: end with the recommended videos and a FULL SCRIPT generated for each one, assembled into the dashboard.
SETUP - ask these in plain language (collect in one batch; skip anything the brief already answers; state assumptions inline)
Ask each question the way a normal creator would understand it. The plain wording is what you SAY; the note in (parentheses) is only for you, do not show the jargon to the user.
"WHAT'S YOUR NICHE OR THE TOPICS YOU WANT SCRIPTS ABOUT?" (required; this is the output niche.)
"INSTAGRAM OR TIKTOK?" (platform. Meedro covers Instagram and TikTok reels ONLY. Never offer YouTube Shorts or other platforms. If they say "both", make the calendar work for both.)
"WHAT ARE YOU SELLING, AND WHERE DO YOU WANT VIEWERS TO END UP?" (e.g. a paid offer, a call, a free trial, a community, an email list. This tells the selling/converting videos what to point to. It is NOT the same as the CTA line on every video - it's the end destination the converting videos drive toward. Use plain words with the user, never say "BOFU".)
"ARE THERE ANY SPECIFIC VIDEOS YOU ALREADY WANT ME TO USE FOR INSPIRATION?" (if yes, use those directly - rule 3 exception.)
"SHOULD I ONLY USE VIDEOS FROM CREATORS IN YOUR NICHE, OR CAN I ALSO BORROW GREAT VIDEO IDEAS FROM OTHER NICHES AND ADAPT THEM TO YOURS?" (sourcing scope. Default: allow other niches, clearly tagged.)
"ANYTHING SPECIFIC YOU WANT? (a certain tone, angle, points to hit, formats to avoid, or extra details to include for each video)" (extra criteria.)
"HOW MANY VIDEOS DO YOU WANT TO PLAN?" and, only if they care, "ANY MINIMUM VIEW COUNT THE ORIGINALS SHOULD HAVE?" (counts. Defaults, all overridable, DON'T dump the jargon on them: 30 videos to shoot, 5 competitors, 9 hook templates, 6 retention structures, a weekly mix of 3 top-of-funnel + 2 middle + 1 bottom, a 7-day shoot plan, originals above ~100K views. Offer a live-tracker version only if relevant.) Keep it friendly and short. Don't ask all of them like a form if the brief already answered some, and never use insider terms (BOFU, TOFU, MOFU, cadence, outlier, "view floor", "top-N") when talking to the user - translate them.
RUN (all Meedro, zero-credit unless the user approves analysis)
PHASE 0 - check_credits (informational). Confirm which watchlist to use, or create_watchlist for this niche.
PHASE 1 - COMPETITORS (default 5). search_account by niche keyword + existing watchlists. add_to_watchlist for any new ones (accepts full Instagram or TikTok URLs; keep off-niche/test creators OUT). Rank by relevance + reach; flag a small-but-strong creator as "one to watch," not a top pick.
PHASE 2 - PULL WINNERS FROM FREE SURFACES ONLY.
videos_watchlist (free) - authoritative data-status surface.
search_viral_videos (free) - run 10+ parallel queries: niche topics AND pattern/format angles (a hook style, a structure) so transplantable patterns from other niches surface too. Analyzed videos return FULL breakdowns here for free; this is the main pool.
The calendar is built ONLY from videos that have full transcripts here (analyzed videos).
PHASE 3 - PATTERN-MATCH SELECTION. Keep a candidate only if it passes ALL: has a usable transcript; has a transplantable pattern (source niche need NOT match - cross-niche allowed); recreates into a quality script for the user's niche + criteria; meets the view floor. RANK survivors for QUALITY, not just reach. Prefer, in order: (1) strong outliers (did far better than that creator's norm - a repeatable pattern, not a one-off boosted post); (2) patterns that clearly transplant to the user's niche; (3) recent enough to still be working; (4) variety of hook/format types. High raw views alone never win a slot. DE-DUPLICATE: do not recommend multiple near-identical videos. If several sources share the same hook + structure, keep the single best one and use the others only as evidence the pattern repeats. The final set should be a VARIED mix of formats/angles, not five versions of one trend. INSUFFICIENT POOL: if fewer videos qualify at zero cost than the user asked for, DEFAULT to shipping a complete, high-quality smaller calendar now (e.g. deliver 18 great ones instead of padding to 30 with weak picks), and tell the user how many qualified + offer (with an estimate) to analyze_profile/analyze_video more creators - incl. outside the niche - to reach the target. Never pad the calendar with low-quality videos to hit a number. Get a clear YES before any spend.
PHASE 4 - VERIFY + AUTO-FIX HOOKS (rule 5) for every selected video and the hero, before anything is shown.
PHASE 5 - HERO. Pick the single highest-signal outlier that also recreates well. It must already have full data (if the user wants an un-analyzed video as hero, run analyze_video on it first - a flat 5 credits, no confirmation prompt, report the cost after). Show Original -> Template -> Recreated with the "hook stays near word-for-word, re-skin don't redesign" note.
PHASE 6 - BUILD ROWS + FULL SCRIPTS. For each recommended video: extract the beat-by-beat skeleton from the transcript; Claude writes a FULL, ready-to-film recreated script for it (this is the deliverable, not a beat outline) - keep the verified hook pattern + pacing + beats + emotional triggers; change angle/topic/examples/wording to the user's niche + criteria. Tag TOFU/MOFU/BOFU; attach the real views as a heat bar; add a one-line shoot direction; attach the SOURCE (link + @creator + real numbers, rule 7) and a "cross-niche - from [niche]" tag where borrowed. Write a full script for EVERY recommended video (if the set is large, lead with the strongest ones and continue through the rest - do not stop at a subset). If the user mentioned they don't show their face, write the script to work as voiceover + on-screen text / b-roll (this shapes HOW you write it, it does not filter which videos are used). Carry any extra user-requested fields.
PHASE 7 - ASSETS + STRATEGY. Assign every recommended video a FUNNEL STAGE (TOFU/MOFU/BOFU) and a DAY across the plan (default 7 days), so the core section can list them day-by-day with their funnel tag (do NOT build a separate shoot-plan section - the videos and the schedule are one thing). Build hook templates (default 9) as fill-in-the-blank from the CORRECTED hooks (templatize logic). Retention structures (default 6) = the recurring beat frameworks. A full-funnel summary = the weekly mix (default 3 TOFU / 2 MOFU / 1 BOFU) + which ideas feed each stage. All counts follow the user's request.
PHASE 8 - QUALITY GATE, then render, then pin questions. Do NOT put any credit/spend number on the dashboard. Only mention spend to the user in chat IF credits were actually used (with prior approval); if the build was zero-credit, don't bring it up.
QUALITY GATE - every script must pass before it enters the dashboard
Structural fidelity: same beat count, pacing, hook pattern as source (hero: near word-for-word). Original wording - not a copy/translation.
Verified hook (rule 5): topic clarity + a reason to keep watching; fits the platform's opening window.
Retention: no dead air; beats connect with tension (complication -> consequence), not flat "and then / and then."
Readability: plain spoken language; short sentences; hook simpler than the body.
Voice / criteria: obeys the user's stated instructions/tone/angle/format; match a supplied voice sample or keep a neutral natural voice and note it was unverified.
CTA: matches the script's funnel stage and points to the user's stated selling destination. If a script fails, fix and re-check; if it can't pass, drop that source and pick another qualifying one.
OUTPUT - one self-contained, presentation-ready .html file
It must look like a finished product someone can present to a team or client - not a raw data dump. All CSS + JS inline, no external fonts/CDNs/frameworks, no browser storage. Opens anywhere, prints clean.

Content writing rule (the visible dashboard text)
Do NOT use long dashes (em dash "-" or en dash "-") anywhere in the generated copy. Write with periods, commas, colons, or parentheses instead. Keep sentences short and clean. (This applies to all human-readable text: hooks, scripts, why-lines, leads, labels.)

Explanations focus on the CONTENT and why it performs (hook, structure, angle, emotion, funnel fit). They never reference tools, data sources, credits, or how the dashboard was built.
